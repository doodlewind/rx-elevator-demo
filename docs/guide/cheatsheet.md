# 速查表 · RxJS 操作符 × 电梯类比

学完九课，你已经把这些操作符用在真电梯上跑过了。这一页把它们按「干什么」分成四组，每个操作符一行：**名字 + 一句电梯类比 + 它在哪一课登场**。需要时回来扫一眼即可。

> 全部从 `'rxjs'` 主入口导入：
> ```ts
> import { of, from, interval, timer, map, scan, switchMap, merge, filter /* ... */ } from 'rxjs'
> ```

## 创建类：从无到有，造一条流

「我手上还没有流，怎么造一条出来？」这一组负责开头。

| 操作符 | 电梯类比 | 出现在 |
| --- | --- | --- |
| `of(a, b, c)` | 把几个已知值依次发出来：开机时「预置」1 楼、3 楼两个目标，发完即结束 | 工具型，配合 `scan` 的初始世界 |
| `from(arr)` | 把一个数组/Promise 摊成一条流：把「待办楼层列表」一层一层放出来 | 工具型 |
| `fromEvent(el, 'click')` | 把 DOM 事件变成流：每次有人按大厅按钮，流上就冒出一个值 | L1 思路（按钮即流） |
| `interval(1000)` | 每隔固定时间发一拍：像电梯每秒「滴答」一下，但**永不结束** | L2 节拍雏形 |
| `timer(0, ms)` | 先等一下再开始，之后按节拍持续发：本教程用它当电梯的「移动节拍」 | L2 · L9 |

<ConceptCard title="为什么本教程偏爱 timer 而不是 interval" icon="🛗">

`interval(ms)` 必须等满一个周期才发第一拍；`timer(0, ms)` 能让你**立刻发第一拍**、之后再按周期走。电梯按下就该动，不该先发愣一秒，所以我们一路用的是 `timer`。

</ConceptCard>

## 变换类：把流里的值加工成新值

「值已经在流上了，我想把它变个样、或者把它展开成一串新值。」

| 操作符 | 电梯类比 | 出现在 |
| --- | --- | --- |
| `map(fn)` | 一进一出，不改时刻只换内容：把请求 `{floor:7}` 变成「电梯在 7 层」一帧状态 | L1 |
| `scan(reducer, seed)` | 像记账本，把「上一刻状态 + 新事件」累加成「这一刻状态」：电梯的目标队列就是这么攒起来的 | L5 · L6 · L9 |
| `switchMap(fn)` | **喜新厌旧**：每来一个新请求，就**取消**上一段还没走完的移动，立刻改去新楼层 | L3 · L4 |
| `mergeMap(fn)` | **来者不拒**：每个请求都展开成自己的子流，**全部并行**同时跑、互不打断 | 多电梯并行思路（L7） |
| `concatMap(fn)` | **老实排队**：一个请求的子流彻底跑完，才轮到下一个，严格先来后到 | 工具型 |
| `exhaustMap(fn)` | **忙时免打扰**：当前子流没跑完时，新来的请求**直接丢弃** | 工具型 |

<ConceptCard title="四兄弟最易混：switchMap / mergeMap / concatMap / exhaustMap" icon="🚪">

它们都做同一件事——「每来一个值，就启动一段子流程（比如『从当前层一层层走到目标层』）」。区别只在于：**当上一段子流程还没结束、新值又来了，怎么办？** 用「同一部电梯接连收到 5 楼、9 楼两个请求」来记：

- **`switchMap`（切换）**：作废 5 楼那段，掉头直奔 9 楼。
  *输出：…6、7、8、9*（5 楼半路被取消，本教程 L3 让电梯改变主意就靠它）
- **`mergeMap`（合并）**：5 楼、9 楼两段同时进行，谁先到的状态先冒出来，交织在一起。
  *适合「**多部**电梯各走各的、谁也不等谁」。*
- **`concatMap`（拼接）**：先把 5 楼这段完整走完，再从头开始走 9 楼，绝不插队。
  *输出：…→5（到站）→…→9（到站），顺序铁定。*
- **`exhaustMap`（耗尽）**：正在去 5 楼，期间 9 楼那一下**被无视**，等到了 5 楼空闲了才肯接新活。
  *像「门还在关、连点没用」——防住了重复触发。*

一句话口诀：**switch 砍旧、merge 并行、concat 排队、exhaust 拒新**。

</ConceptCard>

## 过滤类：决定哪些值能通过

「流上的值太多太杂，我只想放行其中一部分。」

| 操作符 | 电梯类比 | 出现在 |
| --- | --- | --- |
| `filter(pred)` | 只放行满足条件的：上行途中只接「也要上行」的同向呼叫，反向的先不理 | L4 |
| `take(n)` | 取够前 n 个就关流：只看电梯的前 3 帧动画然后收工 | 工具型 |
| `takeWhile(pred)` | 只要条件成立就放行，一旦不成立立刻结束：一层层走，**走到目标层那一刻就停发** | L2 · L3 · L4 |
| `distinctUntilChanged(eq)` | 和上一个放行的值一样就跳过：电梯状态没变化的帧不重复推给界面 | L5 · L6 · L8 |
| `debounceTime(ms)` | 等「安静下来」才认一次：着急的人连按五下，只在停手后算一次呼叫 | L8 |
| `throttleTime(ms)` | 先放一个再冷却：放行第一下，接下来一段时间内的连点全丢，限流不抖 | L8（与 debounce 对照） |

<ConceptCard title="debounceTime vs throttleTime：都治连点，时机相反" icon="⏱️">

同样是「有人疯狂连按楼层键」：

- `debounceTime` **等你停手**——最后一下之后安静了一会儿，才放行那一下（重「最终意图」）。
- `throttleTime` **先认头一下**——立刻响应第一次，然后冷却一段时间无视后续（重「即时反应」）。

电梯呼叫想要的是「你到底要去几楼」，所以本教程清洗输入用的是 `debounceTime`。

</ConceptCard>

## 组合类：把多条流编织成一条

「我有好几条流——按钮流、时钟流、各部电梯的状态流——怎么合到一起？」

| 操作符 | 电梯类比 | 出现在 |
| --- | --- | --- |
| `merge(a$, b$)` | 多条流并到一条，谁来都立刻放行：把「按钮请求流」和「时钟节拍流」汇成一条事件流喂给 `scan` | L5 · L6 · L7 · L9 |
| `concat(a$, b$)` | 一条流彻底放完，才开始下一条：先播完「开门动画」流，再接「关门」流 | 工具型 |
| `combineLatest([a$, b$])` | 任一条更新就把**各条的最新值**凑成一组：把每部电梯的最新状态组合成「整栋楼快照」 | 多电梯快照思路（L7） |
| `withLatestFrom(other$)` | 以主流为节拍，每拍**捎带**另一条流的最新值：时钟每滴答一下，顺手读一次当前目标队列 | 调度取数思路 |
| `zip(a$, b$)` | 严格配对，一对一齐步走：第 1 个配第 1 个、第 2 个配第 2 个，慢的那条会拖住快的 | 工具型 |

<ConceptCard title="merge / combineLatest / zip 三者怎么选" icon="🔀">

都在「合流」，但合的方式不同——还是用电梯举例：

- **`merge`**：按钮按下、时钟滴答……**任何**一条流有动静，就原样放出去。本教程的主力，`merge(requests$, tick$)` 是 L5 之后所有调度的骨架。
- **`combineLatest`**：「3 号电梯刚到 5 层」一更新，就把**全部** 4 部电梯各自的最新位置打包成一份整楼快照——适合渲染总览面板。
- **`zip`**：要求两条流**一一配对**才输出，节奏被慢的一方锁住，日常调度里很少用，但理解它有助于看清前两者「不要求配对」的自由。

</ConceptCard>

## 一张全景图

把九课串起来看，一台完整电梯的数据流大致长这样：

```ts
import { merge, timer, scan, map, filter, switchMap,
         debounceTime, distinctUntilChanged } from 'rxjs'

merge(
  requests$.pipe(            // 按钮流（L1）
    debounceTime(120),       // 防连点（L8）
    distinctUntilChanged(),  // 去重（L8）
  ),
  timer(0, msPerFloor),      // 时钟节拍流（L2）
).pipe(
  scan(reducer, initialWorld), // 累积全栋电梯的状态（L5/L6/L9）
  map(toStates),               // 投影成界面状态（L1）
  distinctUntilChanged(sameState), // 没变化的帧不重发（L5）
)
```

每个操作符你都在前面的课里亲手点过了——这张速查表只是帮你随时叫回它们的名字。

<ConceptCard title="收藏建议" icon="✅">

- 不确定该用变换四兄弟里的哪个？回到那句口诀：**switch 砍旧、merge 并行、concat 排队、exhaust 拒新**。
- 想合流？默认先想 `merge`；要「整体快照」用 `combineLatest`；要「严格配对」才用 `zip`。
- 处理人的连点？想要最终意图用 `debounceTime`，想要即时反应用 `throttleTime`。

</ConceptCard>
