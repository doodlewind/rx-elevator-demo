# 为什么用电梯学 RxJS

如果你查过 RxJS 的文档，大概见过这样的句子：

> Observable 是一个惰性的、可被多次订阅的、关于「随时间推送的多个值」的推送式集合。

每个字都认识，连起来不知道在说什么 —— 这很正常。问题不在你，而在于这些解释**太抽象**：它用 `a`、`b`、`c` 这些没有意义的字母，去解释一套关于「时间」和「变化」的思想。

这套教程换一个办法：**我们只讲一台电梯。**

## 电梯就是一个绝佳的「响应式」系统

想想你每天坐的电梯，它干的事情，几乎就是 RxJS 想表达的一切：

- 有人按楼层按钮 —— 这是**随时间到来的事件**；
- 电梯不会立刻瞬移，而是一层层地动 —— 这是**随时间推送的一串值**；
- 你按了 7 层又改按 3 层，它得**取消**原来的打算 —— 这是 `switchMap` 的「切换」；
- 好几个人在不同楼层按了按钮，它得**排队、合并、按顺序服务** —— 这是 `scan`、`merge`；
- 高峰期一栋楼有好几部电梯**协同调度** —— 这是多条流的合流与分发。

<ConceptCard title="一句话抓住 RxJS" icon="🛗">

**RxJS 就是「电梯调度系统」的通用版本**：把「随时间发生的事件」当作一条**流**，再用一组**操作符**把这条流加工、组合、变换成你想要的另一条流。学会 RxJS，本质上就是学会「像调度电梯一样思考数据」。

</ConceptCard>

## 这套教程怎么带你走

我们设计了 **9 节课**，难度像爬楼梯一样平滑上升，每节课只引入一两个新操作符：

| 课 | 电梯里发生的事 | 你会学到 |
| --- | --- | --- |
| L1 | 按一下按钮，电梯出现在那层 | 流、`map`、订阅 |
| L2 | 电梯一层层地移动过去 | `timer`、`switchMap` |
| L3 | 按了新楼层，旧任务作废 | `switchMap` 的「切换/取消」 |
| L4 | 区分上行、下行 | `filter`、条件子流 |
| L5 | 多个请求排队等待 | `scan` 累积状态 |
| L6 | 真正的电梯调度算法 | reducer 式的 `scan` 状态机 |
| L7 | 一栋楼里多部电梯 | `merge`、`groupBy`、派单 |
| L8 | 连点防抖、开关门延时 | `debounceTime`、`delay` |
| L9 | 完整可玩的模拟器 | 把上面全部拼起来 |

每节课你都会看到三样东西：

1. **能播放的弹珠图** —— 把时间一帧帧往前拨，亲眼看操作符怎么变换流；
2. **能点的真电梯** —— 直接点楼层按钮，看你刚学的那段 RxJS 跑起来；
3. **能改的代码** —— 在 [Playground](/playground) 里把管道拆开、加料、立刻见效。

## 给你的一点准备

你只需要会一点点 JavaScript：知道什么是函数、数组的 `map`、箭头函数。**不需要**任何 RxJS 或「响应式编程」基础 —— 那正是我们要一起建立的。

准备好了吗？先花两分钟建立[最重要的思维模型：一切皆是流](/guide/mental-model)，然后我们就进电梯。
