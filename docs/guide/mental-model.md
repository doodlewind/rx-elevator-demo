# 思维模型：一切皆是流

在按下任何一个楼层按钮之前，先花两分钟换一副「眼镜」。学 RxJS 最大的坎从来不是记操作符，而是**换一种看待程序的方式**。这一页只做一件事：把这副眼镜戴到你脸上。

## 两种取值的方式：你去拿，还是它推给你

想象电梯口的两块牌子。

第一块牌子写着楼层显示，你**想知道电梯在几层，就抬头看一眼**。看一次得一个值，不看就什么都不会发生。这就是你熟悉的普通 JavaScript：

```ts
const floors = [3, 7, 5]   // 值此刻就摆在这里
floors.forEach((f) => console.log(f))  // 你主动去遍历、去取
const now = getCurrentFloor()          // 你主动调用函数去拿
```

数组、普通函数都属于这一类：值是**现成的**，**由你主动去取**。这叫**拉模型（pull）**——你是主动方。

第二块牌子是楼层按钮本身。**你没法「去取一次点击」**，你只能说一句：「以后只要有人按这个按钮，就通知我。」按不按、什么时候按，你说了不算；你能做的只是**预先登记好「来了怎么办」，然后等它推给你**。

```ts
button.addEventListener('click', (e) => {
  // 你不知道这行什么时候跑、跑几次，
  // 但只要有人点，事件就会被「推」进来。
})
```

这叫**推模型（push）**——值**随时间被推给你**，你是被动方。**RxJS 就是把「推模型」做到极致、并且可以像数组一样优雅加工的工具。**

<ConceptCard title="拉 vs 推：谁是主动方" icon="🛗">

- **拉（数组 / 普通函数）**：值现成地躺在那儿，**你主动去取**，取几次由你决定。
- **推（Observable / 事件）**：值**随时间陆续到来**，何时到来由它决定，**你只负责描述「来了怎么处理」**。

电梯里几乎所有有趣的东西——按钮、楼层变化、开关门——都是「推」来的。所以我们需要一套专门驾驭「推」的工具。

</ConceptCard>

## 把现实里的电梯，对应到 RxJS 的零件

好消息是：RxJS 的核心概念，每一个都能在电梯里找到一个看得见摸得着的对应物。记住下面这张对照表，你就掌握了一半。

| 现实里的电梯 | RxJS 里的概念 | 它是什么 |
| --- | --- | --- |
| 那个会被反复按的楼层按钮 | **Observable（流）** | 「随时间到来的一串值」的来源 |
| 「有人按了就通知我」的那份约定 | **Observer（观察者）** | 一组回调：值来了怎么办 / 出错了怎么办 / 结束了怎么办 |
| 真正接上电、开始监听按钮的那一刻 | **Subscription（订阅）** | 把 Observer 接到 Observable 上，让流真正「通电」，并能随时断开 |
| 「把楼层号换算成电梯指令」这种小加工 | **Operator（操作符）** | 输入一条流，输出一条新流的纯函数，如 `map`、`filter` |
| 一连串加工首尾相接的流水线 | **`pipe`（管道）** | 把若干操作符串起来：`stream$.pipe(a, b, c)` |

把这五个零件连起来读一遍：**按钮（Observable）会随时间推出一串值，你通过订阅（Subscription）登记好一份处理约定（Observer），中间用一条管道（pipe）串起若干操作符（operator），把原始的按钮流加工成你真正想要的电梯指令流。** 这句话，就是一整套 RxJS 程序的骨架。

```ts
import { map, filter } from 'rxjs'

const command$ = buttonPresses$.pipe(   // buttonPresses$ 是 Observable（流）
  filter((floor) => floor >= 1),        // operator：扔掉不合法的楼层
  map((floor) => `去 ${floor} 层`),     // operator：把楼层号变成指令
)

const sub = command$.subscribe((cmd) => move(cmd))  // 订阅：流在此刻才真正通电
// sub.unsubscribe()  // 不想听了？随时断开这次订阅
```

注意一个细节：在 `subscribe` 之前，上面的 `command$` **一个值都没流动过**。流是**惰性**的——你只是把流水线**搭好**，直到有人订阅，按钮的值才开始真正沿着管道流下来。这和「数组一写出来值就在那儿」很不一样。

读这张图，请只盯住一件事：**上面进来一个 `3`，下面对齐着出去一个 `去3`；进来 `7`，出去 `去7`。** 操作符 `map` **没有改变事件发生的时间**（圆圈的横向位置纹丝不动），只改变了每个圆圈里**装的值**。

这就是响应式最迷人的地方：一条流经过操作符，变成另一条形状相同、内容不同的流——就像同一段乐谱换了乐器演奏，节奏不变，音色变了。后面每一课，无非都是在玩这个游戏：**拿一条流，用合适的操作符，把它变成我想要的另一条流。**

## 声明式：描述「变成什么」，而不是命令「怎么改」

最后一块、也是最难扭过来的一块拼图：**声明式**。

如果用老办法（命令式）写「按钮 → 电梯指令」，你大概会写成一堆「先做这个、再改那个」的步骤：

```ts
// 命令式：你一步步地命令机器去改状态
let commands = []
for (const floor of pressedFloors) {   // 手写循环
  if (floor >= 1) {                     // 手写判断
    commands.push(`去 ${floor} 层`)     // 手动改一个可变数组
  }
}
```

而响应式让你换一种说法。你不再去**指挥每一步**，而是**描述一条流和另一条流之间的关系**：

```ts
// 声明式：你只描述「输入流 如何 变成 输出流」
const command$ = pressed$.pipe(
  filter((floor) => floor >= 1),
  map((floor) => `去 ${floor} 层`),
)
```

后者**没有循环、没有 `if` 语句、没有手动改动的变量**。你只是在说：「合法的楼层，请变成对应的指令。」**至于值什么时候来、来几个、循环几次，全交给 RxJS 替你打理。** 你描述的是**意图**，不是**步骤**——这就叫声明式。

<ConceptCard title="把这三句话记牢" icon="✅">

- **一切皆是流**：按钮、楼层、开关门……凡是「随时间发生的事」，都看成一条 Observable。
- **操作符把一条流变成另一条流**：`pipe` 把它们串成流水线，不改时间、只换内容（或筛掉、或合并）。
- **声明式地思考**：你描述「输入流 → 输出流」的关系，而不是手写循环和 `if` 去一步步命令机器改状态。

这三句话会贯穿全部 9 节课。每当某课让你犯晕，就回到这一页重读一遍。

</ConceptCard>
